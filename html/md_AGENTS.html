Static analysis workflow

To keep the C code clean and catch potential bugs early, we use Clang's tools.

  1. Run scan-build once – execute from source/:
    cd source && make scan
    This invokes scan-build a single time (no recursive Make invocation) with SCAN_OPTS available for extra flags. If the binary is missing the target prints a message and exits successfully.
  2. Inspect warnings – the analyzer will report dead stores, uninitialized values, etc. Address each warning by reading the source, and when safe, rewrite the code to remove the warning rather than silence it.
  3. Repeat as needed – rerun make scan after each fix until the output reports no bugs, or not too important warnings (an empty report directory). Since the rule is non‑fatal,
  4. Clang‑tidy for style – use make tidy which runs clang-tidy over all .c/.cpp files, using a compile_commands.json if one exists. Again, missing clang-tidy is tolerated.

These targets are part of the regular Makefile.mk and are optional helpers.

Additional analysis can be performed with cppcheck

# direct invocation
cppcheck --enable=all --inconclusive --quiet .
# or via make now that a convenient target has been added
cd source && make cppcheck

It will report informational messages about missing includes and some style issues; treat the findings similarly to scan-build warnings.
