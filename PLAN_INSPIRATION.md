# Auto Slice by Transients — Design Reference

## Objective
Implement a **non-destructive automatic slicing system** based on **audio transients**, inspired by Ableton Live's Simpler.  
The goal is to segment a sample into musically meaningful regions that can be triggered individually.

This document defines the **expected behavior and design constraints** so the agent can verify that the plugin implementation follows equivalent concepts.

---

# Core Concept

A **slice** represents a playback region starting at a detected **transient onset**.

Slices are stored as **markers referencing positions in the source sample**, not as separate audio buffers.

Key properties:

- Slicing is **non-destructive**
- Slices are defined only by **sample index positions**
- Slices partition the playback region into **ordered segments**

Each slice `i` spans:

```
start = slice[i].position
end   = slice[i+1].position
```

The final slice ends at the **region end marker**.

---

# Playback Region

Two markers define the allowed slicing region:

```
region_start
region_end
```

Transient detection must **only analyze this interval**.

Any slices outside this region are invalid.

---

# Automatic Transient Detection

The system detects **onset events** within the playback region.

Typical detection signals may include:

- amplitude envelope derivative
- spectral flux
- energy rise
- high-frequency transient emphasis

The exact detection algorithm is implementation dependent, but it must satisfy:

- strong attacks produce slice markers
- quiet regions do not generate markers
- closely spaced transients may be merged

---

# Sensitivity Parameter

A **Sensitivity** parameter controls detection threshold.

Higher sensitivity:

- lowers detection threshold
- produces **more slices**

Lower sensitivity:

- raises threshold
- produces **fewer slices**

Behavior requirements:

```
sensitivity ∈ [0..1]
```

Mapping guidelines:

```
threshold = f(sensitivity)
```

Typical behavior:

| Sensitivity | Result |
|-------------|--------|
| low         | only strong attacks detected |
| medium      | typical rhythmic hits |
| high        | many micro-transients |

---

# Slice Limit

The system must enforce a **maximum slice count**.

Reference design:

```
MAX_SLICES = 64
```

If more transients are detected:

1. Rank candidates by strength
2. Keep strongest N events

---

# Slice Marker Types

Slices can be either:

### Automatic slices

Generated by transient detection.

Properties:

```
slice.type = AUTO
```

These may be regenerated when sensitivity changes.

---

### Manual slices

User-created markers.

Properties:

```
slice.type = MANUAL
```

Rules:

- manual slices are **never removed automatically**
- manual slices override auto-detection

---

# Manual Editing

User interactions must support:

### Add slice
Double-click inside region.

```
slice.type = MANUAL
```

### Delete slice
Double-click existing slice.

### Move slice
Drag marker to new position.

Constraints:

```
slice[i] < slice[i+1]
```

Slices must remain ordered.

---

# Hybrid Mode (Auto + Manual)

When using transient slicing:

Manual slices must remain stable even if sensitivity changes.

Algorithm:

```
1 detect auto slices
2 merge with manual slices
3 sort by position
4 enforce slice limit only on auto slices
```

Manual slices always take priority.

---

# Slice Visualization

Waveform display shows slice markers.

Recommended representation:

| Marker Type | Color |
|--------------|------|
| Auto slice   | blue |
| Manual slice | white |

Markers are vertical lines at slice positions.

---

# Playback Behavior

Each slice becomes a **triggerable playback unit**.

Triggering slice `i` plays:

```
start = slice[i]
end   = slice[i+1]
```

Optional playback modes:

- monophonic
- polyphonic
- sequential (play-through)

These are outside the slicing algorithm and may be implemented independently.

---

# Algorithm Outline

```
function autoSlice(sample, region_start, region_end, sensitivity):

    signal = extract(sample, region_start, region_end)

    candidates = detect_transients(signal)

    scored = score_transients(candidates)

    threshold = sensitivity_to_threshold(sensitivity)

    filtered = keep_above_threshold(scored, threshold)

    sorted = sort_by_strength(filtered)

    auto_slices = keep_first(sorted, MAX_SLICES)

    merge_with_manual(auto_slices)

    sort_by_position()

    return slices
```

---

# Validation Criteria

The implementation is considered conceptually aligned if:

- slicing is **non-destructive**
- slices originate from **transient detection**
- sensitivity controls **detection density**
- manual slices persist through regeneration
- slices define **playable segments**
- a **maximum slice limit** exists

Exact detection algorithm does **not need to match Ableton's implementation**, only the behavior model.
